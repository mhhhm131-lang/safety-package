## ٠. الفهم أولاً

### ٠-١ الغاية
**ليست** "إضافة ميزة تحرير" — بل:
> إلغاء الفجوة بين الخطة الموحدة والواقع المختلف في كل فرع/إدارة، حتى يكون لدى كل فرع نسخة محدّثة من خطته الفعلية على النظام.

### ٠-٢ المشكلة الحقيقية

**الحالة الحالية:**
- الخطة الموحدة تقول: "استدعاء الطبيب الداخلي"
- الفرع ليس فيه طبيب → يقول "هذا لا ينطبق علينا"
- يعدّلها يدويّاً (Word/ورقة) → النسخة الرقمية عتيقة
- الفريق يستخدم نسخة قديمة أو ملموسة → **نتائج مختلفة عن الخطة**

**السبب الجذري:**
الخطة **موحدة** لكن الواقع **متعدد**:
- فروع لها موارد مختلفة (طبيب، إسعاف خارجي)
- إدارات مسؤولة مختلفة (شؤون إدارية، مرافق)
- أشخاص مختلفين (الفني، المنسق، المدير)

### ٠-٣ الحل المقترح

```
الخطة الأساسية (البنية الموحدة للمعهد)
         ↓
    [البيانات المشتركة]
         ↓
نسخة مخصصة لكل فرع/إدارة
(تحتفظ بالبنية، تغيّر المحتوى)
```

**النتيجة:**
- ✅ نفس البنية (لا تعديل الكود)
- ✅ محتوى مختلف (بيانات محدّثة)
- ✅ نسخة دائماً على النظام (لا Word ولا ورقة)
- ✅ كل فرع يرى خطته الفعلية

## ٢. المشكلة التفصيلية

### ٢-١ سيناريوهات واقعية

#### الخطط (مثال)

**المركز الرئيسي — خطة الاستجابة الطبية:**
```
١. تقييم الحالة بواسطة: أي شخص حاضر
٢. استدعاء الطبيب الداخلي: الطبيب أحمد (الملز ٥)
٣. نقل المصاب: إلى العيادة الداخلية (الملز ٧)
٤. الإجلاء: إن لزم → مستشفى الملك فيصل
٥. الإبلاغ: مسؤول السلامة + الدفاع المدني
```

**فرع بدون طبيب (مثلاً القصيم):**
```
✗ الطبيب الداخلي غير موجود
✗ العيادة الداخلية غير موجودة
→ الخطة لا تنطبق!

الفرع يعدّلها يدويّاً:
١. تقييم الحالة
٢. استدعاء الإسعاف الخارجي: ٩٩٧
٣. نقل المصاب: إلى أقرب مستشفى
٤. الإبلاغ: مسؤول السلامة المركز + الدفاع المدني
```

#### جدول المقارنة (مثال)

**الملز (المركز الرئيسي) — جاهزية ٩٠%:**
```
البند: المخطط الموضوعي للسلامة
└─ اللائحة: يجب أن يكون موجوداً
└─ الوضع الحالي: ✓ موجود
└─ الإجراء: معتمد منذ ٢٠٢٥
```

**القصيم (فرع) — جاهزية ٦٠%:**
```
البند: المخطط الموضوعي للسلامة
└─ اللائحة: يجب أن يكون موجوداً
└─ الوضع الحالي: ✗ غير موجود
└─ الإجراء: جاري الإعداد (موعد النهاية: ديسمبر ٢٠٢٦)
```

**النتيجة (للخطط والمقارنة معاً):**
- ❌ النسخ على النظام قديمة
- ❌ الفريق يستخدم ورقة أو Word
- ❌ لا توثيق للتعديلات
- ❌ تحديثات مفقودة عند تدريب جديد
- ❌ لا يُعرف من مسؤول عن الإجراء في كل فرع

### ٢-٢ الأسباب

| السبب | التفصيل |
|-------|---------|
| **موارد مختلفة** | بعض الفروع بها طبيب، بعضها لا |
| **إدارات مختلفة** | المسؤول عن الصيانة يختلف |
| **أشخاص مختلفين** | الأسماء والأرقام تختلف |
| **مراحل مختلفة** | الفرع قد يكون بدون بعض الأماكن |
| **موقع مختلف** | قرب/بعد المستشفى أو الدفاع المدني |

## ٣. الحل المقترح

### ٣-١ المبدأ

```
نفس البنية (الهيكل) + محتوى مختلف (البيانات)
```

**ينطبق على أربعة عناصر:**

| العنصر | الموحد (لا يتغير) | المخصص (يتغير) |
|--------|------------------|-----------------|
| **خطة السلامة/الاستجابة** | عناوين البنود | الأسماء والأرقام والإدارات |
| **مثال** | "١. تقييم الحالة" | من (أي شخص) |
| | "٢. استدعاء" | من/ماذا (طبيب داخلي vs إسعاف خارجي) |
| | "٣. النقل" | أين (عيادة vs مستشفى) |
| **بطاقة الدور** | الدور والوصف | الاسم والإدارة والمكان |
| **جدول المقارنة** | الأعمدة والبنود | الوضع الحالي والإجراء والمسؤول والموعد |
| **مثال** | "البند: المخطط الموضوعي" | "الوضع: ✓ موجود" / "الوضع: ✗ قيد الإعداد" |

### ٣-٢ البنية التقنية

```sql
-- الخطة الأساسية (موحدة للمعهد)
plans (id, name, type, version)
  مثال: (1, "خطة الاستجابة الطبية", "response", "1.0")

-- محتوى الخطة الأساسي (لا يتغير)
plan_items (id, plan_id, item_number, title, description)
  مثال: (1, 1, "1", "تقييم الحالة", "بواسطة أي شخص حاضر")

-- تخصيصات الفرع (جديد)
plan_specializations (id, plan_id, department_id, item_id, value_key, value)
  مثال: (1, 1, 5, 1, "responsible_person", "أي شخص حاضر")
         (2, 1, 5, 2, "responsible_person", "الإسعاف الخارجي 997")
         (3, 1, 5, 3, "location", "أقرب مستشفى")
```

**عند القراءة:**
```
إذا وجدت تخصيص → عرضه
إلا → عرض الأساسي
```

### ٣-٣ سير العمل

#### الحالة أ: مركز رئيسي (يستخدم الأساسي)
```
المستخدم: مسؤول السلامة
الإجراء: يفتح خطة الاستجابة الطبية
النتيجة: يرى الخطة الأساسية (لا تخصيصات)
```

#### الحالة ب: فرع يحتاج تخصيص
```
المستخدم: مدير إدارة الشؤون الإدارية
الإجراء: يفتح خطة الاستجابة الطبية
الظهور: "هذا الجزء غير قابل للتطبيق في إدارتك — هل تريد تعديله؟"
التعديل: يضغط تعديل → يملأ: "استدعاء الإسعاف الخارجي ٩٩٧"
الحفظ: يُحفظ التخصيص (لا يؤثر على الأساسي)
النتيجة: المرة القادمة يرى نسخته المحدّثة
```

## ٤. التفاصيل

### ٤-١ ما الذي يُمكن تخصيصه

#### أ) الخطط والبطاقات

| العنصر | مثال على التخصيص | من الذي يعدّل |
|--------|------------------|-----------------|
| **أسماء الأشخاص** | الطبيب أحمد → إسعاف خارجي | مدير الإدارة |
| **أرقام الاتصال** | `0123456` | مدير الإدارة |
| **الأماكن** | العيادة الداخلية → مستشفى الملك | مدير الإدارة |
| **الإدارات المسؤولة** | شؤون إدارية | مدير الإدارة |
| **البنود الزائدة** | إذا كان البند لا ينطبق → خفيه | مدير الإدارة + موافقة مسؤول سلامة |
| **أرقام النماذج** | الدورية: ٣ شهور → ٦ شهور | مسؤول السلامة فقط |

#### ب) جدول المقارنة

| العنصر | مثال على التخصيص | من الذي يعدّل |
|--------|------------------|-----------------|
| **الوضع الحالي** | ✓ موجود / ✗ غير موجود | مدير الإدارة |
| **الإجراء المتخذ** | "جاري الإعداد" أو "مكتمل" | مدير الإدارة |
| **المسؤول** | اسم الشخص المسؤول | مدير الإدارة |
| **الموعد النهائي** | تاريخ الانتهاء المتوقع | مدير الإدارة |
| **ملاحظات** | تفاصيل المانع أو المسبب | مدير الإدارة |

### ٤-٢ ما الذي لا يُمكن تخصيصه

**الخطط والبطاقات والمقارنة:**
```
❌ عناوين البنود (البنية موحدة)
❌ عدد البنود (يُمكن إخفاء فقط، لا حذف)
❌ الأماكن الأساسية (HZ-00 إلى HZ-08)
❌ أنواع البلاغات (عادي، سري، عاجل)
❌ متطلبات اللائحة (الأعمدة في المقارنة)
```

### ٤-٣ الصلاحيات

| الدور | الصلاحية |
|-------|---------|
| **مدير الإدارة** | تعديل التخصيصات الخاصة بإدارته فقط |
| **مسؤول السلامة** | رؤية كل التخصيصات، الموافقة على الحذف |
| **الإدارة العليا** | رؤية فقط (دون تعديل) |

## ٥. خطوات التطبيق

### ٥-١ المرحلة ١: التصميم (الآن)
- [ ] وثيقة التصميم (هذه الوثيقة)
- [ ] رسم الشاشات (كيف يبدو التعديل)
- [ ] اعتماد من المستخدم

### ٥-٢ المرحلة ٢: الكود (الأسبوع ١)
- [ ] جداول `plan_specializations` في قاعدة البيانات
- [ ] وظائف القراءة (أساسي + تخصيص)
- [ ] وظائف الكتابة (حفظ التخصيص)
- [ ] اختبارات الوحدة

### ٥-٣ المرحلة ٣: الواجهة (الأسبوع ٢)
- [ ] شاشة عرض الخطة (مع تنبيه التخصيص)
- [ ] شاشة التعديل (نموذج بسيط)
- [ ] تاريخ التعديلات (من عدّل ومتى)
- [ ] اختبار على جهاز المستخدم

### ٥-٤ المرحلة ٤: النشر
- [ ] بيانات اختبار (خطط موحدة + تخصيصات)
- [ ] نقل الخطط الحالية إذا كانت موجودة
- [ ] تدريب الإدارات على التعديل
- [ ] موافقة المستخدم النهائية

## ٦. السؤال المهم: هل نبدأ؟

**قبل الإجابة — أتأكد:**

```
☑ هل هذا الفهم صحيح؟
  → كل فرع/مبنى قد يحتاج تعديلات محلية على:
    • خطط السلامة
    • خطط الاستجابة
    • بطاقات الأدوار
    • جدول المقارنة (الوضع الحالي والجاهزية)

☑ هل البيانات (الأسماء، الأرقام، الحالة) قابلة للتغيير؟
  → نعم، البيانات قابلة للتغيير دون ضرر الكود

☑ هل هذا يحقق الغاية؟
  → نعم، كل فرع سيكون لديه نسخة محدّثة على النظام
  → كل فرع يرى وضعه الفعلي وجاهزيته

☑ هل الكود سيتحمل هذا؟
  → نعم، الكود يقرأ البيانات فقط (لا يعتمد على قيم محددة)
```

**القرار المطلوب:**
```
هل نبدأ بالمرحلة ١ (التصميم والرسومات) للأربعة عناصر؟
```
