# تصميم ملفات المشاريع — أسلوب McKinsey

مهارة التصميم الاحترافي والمبدع لملفات المشاريع.

## ١. المبدأ الأساسي — Pyramid Principle

```
        ┌─────────────────┐
        │   الإجابة أولاً  │  ← ابدأ بالتوصية/النتيجة
        │  (Answer First) │
        └────────┬────────┘
                 │
     ┌───────────┼───────────┐
     │           │           │
┌────▼────┐ ┌────▼────┐ ┌────▼────┐
│ حجة ١   │ │ حجة ٢   │ │ حجة ٣   │  ← الحجج الداعمة (٣ عادةً)
└────┬────┘ └────┬────┘ └────┬────┘
     │           │           │
┌────▼────┐ ┌────▼────┐ ┌────▼────┐
│ بيانات  │ │ بيانات  │ │ بيانات  │  ← الأدلة والبيانات
└─────────┘ └─────────┘ └─────────┘
```

### القاعدة الذهبية
**لا تبدأ بالتفاصيل وتنتهي بالنتيجة — ابدأ بالنتيجة ثم ادعمها.**

## ٢. إطار SCQA — افتتاح القصة

| العنصر | المعنى | مثال (حزمة السلامة) |
|--------|--------|---------------------|
| **S** - Situation | الوضع الحالي | مبنى المعهد يستقبل ٣٠٠٠ شاغل يومياً |
| **C** - Complication | المشكلة/التعقيد | لا يوجد من يتصرف في الدقائق الأولى لأي حالة طارئة |
| **Q** - Question | السؤال الضمني | كيف نُلغي هذه الفجوة الزمنية؟ |
| **A** - Answer | الجواب/التوصية | نظام سلامة جاهز يُكلّف الموجودين بالاستجابة الفورية |

### القالب
```
[الوضع]: المعهد يخدم آلاف المستفيدين يومياً...
[المشكلة]: لكن لا يوجد نظام يضمن الاستجابة في الدقائق الأولى...
[الحل]: لذلك أعددنا نظاماً متكاملاً يجعل كل فرد يعرف دوره مسبقاً.
```

## ٣. هيكل العرض — ٣ طبقات

### الطبقة ١: الملخص التنفيذي (١-٢ صفحة)
**لصانع القرار الذي لن يقرأ أكثر من هذا**

```
┌─────────────────────────────────────┐
│         الملخص التنفيذي             │
├─────────────────────────────────────┤
│ • المشكلة (جملة واحدة)              │
│ • الحل (جملة واحدة)                 │
│ • التوصية (جملة واحدة)              │
│ • ما المطلوب (قرار واضح)            │
├─────────────────────────────────────┤
│ الأرقام الرئيسية: ١٧ | ٢١ | ٧٨      │
└─────────────────────────────────────┘
```

### الطبقة ٢: التفاصيل الداعمة (٥-١٠ صفحات)
**للمهتم بفهم الحجج**

### الطبقة ٣: الملاحق (حسب الحاجة)
**للمدقق الذي يريد التفاصيل الكاملة**

## ٤. قاعدة الشريحة الواحدة

### فكرة واحدة = شريحة واحدة

| العنصر | القاعدة |
|--------|---------|
| **العنوان** | جملة كاملة تُلخّص الرسالة (Action Title) |
| **المحتوى** | دليل واحد يدعم العنوان |
| **القراءة** | ٣٠ ثانية كافية لفهم الرسالة |

### مثال: العنوان الفعّال
```
❌ ضعيف: "إحصائيات الإصابات"
✓ قوي: "انخفضت الإصابات ٤٠٪ بعد تطبيق النظام"

❌ ضعيف: "فرق الطوارئ"
✓ قوي: "٢١ فرد مدرّب يغطون كل المبنى على مدار الساعة"
```

## ٥. MECE — التنظيم المنطقي

### Mutually Exclusive, Collectively Exhaustive
**متبادل الاستبعاد، شامل بالكامل**

```
✓ MECE                    ❌ ليس MECE
┌─────────────┐           ┌─────────────┐
│ المبنى      │           │ المبنى      │
├─────────────┤           ├─────────────┤
│ • الأقبية   │           │ • الأقبية   │
│ • الطوابق   │           │ • المكاتب   │  ← تداخل
│ • السطح    │           │ • الطوابق   │  ← تداخل
└─────────────┘           │ • القاعات   │  ← ناقص
                          └─────────────┘
```

### تطبيق على حزمة السلامة
```
✓ MECE: ٨ أصناف مواقع + مركز السلامة
- لا تداخل (كل مكان في صنف واحد)
- شامل (لا مكان خارج التصنيف)
```

## ٦. التصميم البصري

### الألوان
| اللون | الاستخدام |
|-------|----------|
| **الأساسي** (أخضر داكن) | العناوين، العناصر الرئيسية |
| **الثانوي** (ذهبي) | التأكيد، الأرقام المهمة |
| **الخطر** (أحمر) | المشاكل، التحذيرات |
| **النجاح** (أخضر فاتح) | الإنجازات، الحلول |
| **المحايد** (رمادي) | النصوص الثانوية |

### الخطوط
| العنصر | الحجم | الوزن |
|--------|-------|-------|
| العنوان الرئيسي | ٢٤-٣٦ | Bold |
| العنوان الفرعي | ١٨-٢٠ | Bold |
| النص الأساسي | ١٢-١٤ | Regular |
| الملاحظات | ١٠-١١ | Regular |

### المساحات البيضاء
- **لا تملأ كل المساحة** — الفراغ يوجه العين
- **هامش موحد** — ٦٤px من الجوانب
- **تباعد منطقي** — العناصر المتصلة قريبة

## ٧. الرسوم البيانية

### اختيار النوع المناسب

| نوع البيانات | الرسم المناسب |
|--------------|---------------|
| مقارنة كميات | أعمدة (Bar) |
| تغير عبر الزمن | خطي (Line) |
| نسب من الكل | دائري (Pie) — حد أقصى ٥ أجزاء |
| علاقة متغيرين | نقاط (Scatter) |
| تدفق/عملية | مخطط تدفق (Flow) |
| هيكل | شجرة/هرم |

### قواعد الرسوم
1. **عنوان واضح** يُلخّص الرسالة
2. **تسميات محاور** كاملة
3. **وحدات قياس** واضحة
4. **مصدر البيانات** مذكور
5. **لون واحد للتركيز** — لا قوس قزح

## ٨. الأرقام — كيف تُعرض

### القاعدة: الرقم وحده لا يكفي

```
❌ ضعيف:
┌─────────────┐
│     ٧٨      │
│  نظام فحص  │
└─────────────┘

✓ قوي:
┌─────────────────────────────────┐
│           ٧٨                    │
│       نظام فحص                  │
│ ٦٦ في المواقع + ١٢ حريق مركزي  │
│ = تغطية كاملة للمبنى            │
└─────────────────────────────────┘
```

### الأرقام الثلاثة
- اعرض ٣ أرقام رئيسية كحد أقصى في الشريحة
- الرقم + السياق + المعنى

## ٩. الجداول — متى وكيف

### متى تستخدم جدول
- مقارنة عناصر متعددة
- عرض بيانات منظمة
- قوائم مع خصائص

### قواعد الجداول
| القاعدة | التطبيق |
|---------|---------|
| عمود المقارنة أولاً | الأسماء/العناصر على اليمين |
| محاذاة الأرقام | يمين للأرقام العربية |
| تظليل التبادلي | صفوف بالتناوب لسهولة القراءة |
| حد أدنى من الخطوط | خطوط فاصلة فقط عند الحاجة |

## ١١. Storyline — بناء القصة

### الخطوات
1. **حدد الرسالة الرئيسية** (ماذا تريد أن يفعل القارئ؟)
2. **اكتب عناوين الشرائح فقط** (كجمل كاملة)
3. **اقرأ العناوين بالتسلسل** (هل تروي قصة متماسكة؟)
4. **ثم صمم المحتوى** (بعد اكتمال القصة)

### مثال: Storyline حزمة السلامة
```
١. المعهد يواجه فجوة زمنية بين الحدث والاستجابة
٢. السبب: لا أحد مكلّف بالتصرف في الدقائق الأولى
٣. الموارد المادية موجودة (٧٠٪) لكن التشغيل غائب (١٠٪)
٤. الحل: نظام يُكلّف الموجودين بالاستجابة الفورية
٥. النظام يقسم المبنى إلى ٩ مناطق مستقلة ومتصلة
٦. كل منطقة لها فريق وخطة ونماذج فحص
٧. النظام جاهز — ويحتاج قرار اعتماد فقط
٨. الاعتماد يحمي المعهد — والتأخير يُعرّضه للمخاطر
```

## ١٢. So What? — اختبار الأهمية

### لكل معلومة، اسأل: "وماذا يعني هذا؟"

```
المعلومة: لدينا ٢١ بطاقة دور
So What?: كل فرد في فرق الطوارئ يعرف دوره مسبقاً
So What?: لا ارتباك عند الطوارئ
So What?: استجابة فورية وفعّالة
```

### إذا لم تستطع الإجابة على "So What?" — احذف المعلومة.

## ١٣. المراجعة النهائية — Checklist

```markdown
## قبل التسليم

### المحتوى
- [ ] الرسالة الرئيسية واضحة من الصفحة الأولى
- [ ] كل شريحة لها فكرة واحدة فقط
- [ ] العناوين جمل كاملة (Action Titles)
- [ ] كل معلومة تجتاز اختبار "So What?"
- [ ] التنظيم MECE (لا تداخل، لا فجوات)

### التصميم
- [ ] الألوان متناسقة ومحدودة
- [ ] الخطوط موحدة
- [ ] المساحات البيضاء كافية
- [ ] الرسوم مُعنونة ومُوثّقة
- [ ] الأرقام لها سياق ومعنى

### الجودة
- [ ] لا أخطاء إملائية
- [ ] الأرقام متسقة في كل الملف
- [ ] المراجع والمصادر مذكورة
- [ ] رقم الصفحة في كل شريحة
```

## ١٤. تطبيق على حزمة السلامة

### الملخص التنفيذي (صفحة واحدة)
```
المشكلة: فجوة زمنية بين الحدث والاستجابة
الحل: نظام سلامة يُكلّف الموجودين بالاستجابة الفورية
المطلوب: قرار اعتماد — لا يُلزم بتمويل

┌─────────┬─────────┬─────────┐
│   ١٧    │   ٢١    │   ٧٨    │
│  خطة   │ بطاقة   │  نظام   │
│         │  دور   │  فحص   │
└─────────┴─────────┴─────────┘

الخيار: اعتماد → حماية | تأخير → مخاطر
```

### البطاقات الأربع
```
١. ٨+١ أصناف ← لكل مكان طبيعته
٢. مستقل ومتصل ← جاهزية محلية + تنسيق مركزي
٣. من·ماذا·كيف·متى ← لا ارتباك
٤. سياسة→خطط ← مبني على أساس صحيح
```
